## 1. 総評

- 4教材とも「計画 → 育成・記録 → 評価 → 振り返り」の流れがあり、学習指導要領 B の流れに沿っている。動作中のエラーは0件、タッチ対象もほぼ44px以上。
- **回帰なし**: confirm/alert/prompt は0件。自作の確認ダイアログ(kzConfirm)と B1 のオーバーレイ・B2 のモーダルは、全画面サイズで画面内に収まりボタンも押せた。
- ただし、中学生が使うと「学びがゆがむ」「書いたものが消える・切れる」問題がまだある。主なものは次の4種類。
  1. **シミュレーションの因果がおかしい**: B3 は何をしても★3(水替え・そうじなしでも)。B3 の溶存酸素は26℃より上で水温を上げるほど増える(逆)。B2 の原因さがしは、ほぼ毎回「天気による光不足」が正解になり、生徒が直せない原因を答えさせられる。
  2. **内容の誤り・矛盾**: B1 のウズラのひなは「保温35℃」と言いながら35℃で「高温注意」。B4 は休みに合わせて「開花」「収穫」まで前倒しする。B2 のダイズは14日で開花。ニワトリの説明など。
  3. **提出物・データが消える・切れる**: B1・B3・B4 は印刷すると振り返りの文章が枠で切れる(B1 は例文が回答のように印刷)。B1 は日付を変えると今日の記録が消える・保存ボタンを押さずにタブを移ると入力が消える。B3 は30日の結果が確認なしで消える。B4 は誤って完了にすると計画の順番がこわれる。
  4. **ふりがなと操作のバラバラ**: B1・B3・B4 は本文にふりがながほぼない(クイズ・計画書は0件)。ふりがな・文字サイズの場所とボタンが教材ごとにちがい、メニューの「ふりがな」は教材に効かない。タブの見た目・番号・色(B3 だけ青緑)もそろっていない。

## 3. 改善の方針

- **教材の中身(目的・画面構成・タブの数)は変えない。** 誤り・矛盾・データ消失を直し、4教材の操作と見た目をそろえる。
- 単一HTML・外部通信なし・file:// で動作、保存キーは b1_〜b4_ のまま。新しく増やすキーは下の共通ルールの3つだけ(hub_ruby・hub_fs・b?_reflstat)。
- confirm/alert は使わず kzConfirm/kzAlert を使う(全画面での切れ対策を維持)。
- 既存の保存データ(生徒がすでに入力したもの)は読みこめるようにする(形を変える場合は変換する)。

### 共通ルール(4教材とメニューで同じにする)

| 記号 | 内容 |
|---|---|
| K1 ふりがな・文字サイズを1つの設定に | 共通キー `hub_ruby`('1'/'0')と `hub_fs`(14〜26px、初期18)を4教材とメニューが読み書きする。どこで切りかえても、開いているほかの画面にも `storage` イベントですぐ反映。共通部品 `kzPrefs` を各HTMLに入れる。 |
| K2 同じボタンを同じ場所に | 単体で開いたとき、各教材の見出しの右に「ふりがな」「A−」「A＋」の3つ(同じ文字・同じ形・44px以上、ふりがなは押した状態を表示)。B2 は文字サイズを追加、B1 は「使い方」タブの中だけでなく見出しにも置く。上限・下限ではボタンを無効にする。 |
| K3 メニューの中では見出しを1つに | メニューの中(iframe)で開いたときは、教材側の大きな見出し行を隠し、「ふりがな」「A−」「A＋」はメニューの上の帯に置く(B1 の名前ボタンだけは細い行で残す)。上の固定部分が約180px→約115pxになる。 |
| K4 タブの見た目をそろえる | タブの帯は濃い緑、選択中のタブは白地(ページの地色)に濃い緑の太字。B2〜B4 は「① はじめに」のように丸数字＋名前(B3 の「1」バッジを ①〜⑤ に)。B1 は道具として行き来するので絵文字アイコンのまま(番号なし)、色と選択中の形だけそろえる。B3 の見出し・タブ・ボタンの色を緑系にそろえる(水そうの絵の青はそのまま)。文字を大きくしてもタブが画面からはみ出さない(折り返すか短い名前にする)。 |
| K5 印刷で文章を切らない | 印刷のときは textarea を隠し、全文を表示する印刷用の要素(未記入は「(未記入)」)を出す。B1・B3・B4 の振り返り、B3 の計画書、B4 の評価欄。例文(placeholder)は印刷しない。 |
| K6 確認ダイアログ | 消える操作はすべて kzConfirm(danger: 赤ボタン・キャンセルに最初のフォーカス)で、文に「何が消えるか」を書く。B2 の全消去・新しく始める・再挑戦も kzConfirm に切りかえる。 |
| K7 振り返りの形 | 先頭に「組」「番号」「名前」の3つの欄(B1 に組・番号を追加、B4 の1つの欄を3つに、B3 の計画書にも同じ欄)。自己評価は「◎ よくできた/○ できた/△ もう少し」にそろえる(B1 の★1〜5 は ◎○△ に置きかえ、保存ずみの★は 5→◎、3〜4→○、1〜2→△ に変換)。本文は自動保存し、「最後に保存 hh:mm」を表示。 |
| K8 ふりがな | 共通の用語辞書(徒長・摘芯・誘引・出穂・積算温度・溶存酸素・家畜化・外来生物 など)と、画面の文字に自動でルビを付ける共通部品 `kzRuby` を作り、B1・B3・B4 に入れる(B2 は今の自動ルビのまま、読みを辞書とそろえる)。クイズ・計画書・振り返り・作業名にも付ける。むずかしい作業用語は、タップで短い説明が出るようにする(B4)。 |
| K9 振り返りの書きぐあい | 各教材が `b?_reflstat` = {filled, total} を保存し、メニューのカードを「✅ 書いた / 📝 書きかけ / ✏️ まだ」の3段階で表示する。 |

## 4. 教材ごとの改善内容

各IDのくわしい直し方は findings の「直し方」に従う。ここでは方針がちがうところだけ書く。

### メニュー・ガイド(H)
- H-01: 生徒向けの順番を「① B2・B3 で育成環境の調節を知る → ② B4 で計画 → ③ B1 で育てながら記録 → ④ 振り返り」にし、先生用ガイドと合わせる。カードにも「おすすめ①〜③」の印。
- H-02・H-03・H-04: K1〜K3 のメニュー側(上の帯に「ふりがな」「A−」「A＋」、メニュー画面の文字サイズにも反映)。
- H-05・H-07: K4 にあわせて使い方ページの説明を直す。FAQ の「文字が小さい・ふりがなを消したい」は「上の帯のボタン」に統一。
- H-06: K9 の3段階表示。H-08: B2 の保存テスト用キーを消す。
- 先生用ガイド(本体の中と dist/先生用ガイド.html)を変更点にあわせて直す(設定の共通化、B4 の観察の扱い、B3 の★の基準、実機で確認してほしいこと)。

### B1 育成日誌＋成長予測(27件すべて)
- 高: B1-01(日付変更は新しい記録として扱う)・02(K5)・03(自動保存)・04(ウズラは日齢ごとの適温)・05(K8)。
- 中: 06〜18。B1-10 は作物に適期(月)を持たせ、計画で適期外なら警告。予測には「季節が変わると気温も変わる」注記を付ける(月ごとの平年値までは入れない)。B1-11 は作業予定の「収穫」を「収穫(目安)」とし、予測画面に「作業予定は日数の目安、予測は記録した気温からの計算」とちがいを書く。トマトの定植は「1番花が咲くころ(種まき後55日ごろ)」に直す。B1-12 は式を「くわしく知りたい人へ」に折りたたみ、R² は ◎○△ の「当てはまりのよさ」にする。B1-17 は「課題」欄・計画を直した理由の記録・評価の環境/社会の欄を追加。B1-18 は K2。

### B2 育成環境コントローラ体験(27件すべて)

## 5. 進め方

1. **共通部品とメニュー**(worker 1つ): kzPrefs・kzRuby(用語辞書)・印刷用部品を作り、メニューの帯・使い方・先生用ガイドを直す。
2. **B1〜B4 の改善**(worker 4つを同時に): 1. の共通部品を入れ、上の内容を直す。各 worker が自分の教材を Playwright で確認する。
3. **確認と再ビルド**(レビュー担当): 高・中の項目と回帰(ダイアログが画面内に収まる、confirm/alert なし、保存キー)を確認し、統合HTML・先生用ガイド・zip を作り直す。

改善作業は opus medium の worker、レビュー・計画・最終確認は opus high で行う。
