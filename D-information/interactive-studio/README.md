# 双方向コンテンツ制作スタジオ

作成：技術 岡田

中学校技術・家庭科（技術分野）D「情報の技術」(2)『ネットワークを利用した双方向性のあるコンテンツのプログラミングによる問題解決』向けの制作教材です。計画書 [`../review/計画/plan-I5-interactive-studio.md`](../review/計画/plan-I5-interactive-studio.md) の MVP（ブロック式エディタ、ブロック⇔テキストの相互表示、UI部品を置いて動かす実行ビュー、ブラウザ内の擬似サーバー、デバッグ機能）を実装しています。

## すぐに使う

- **いちばん簡単**: `dist/interactive-studio.html` をダブルクリックしてブラウザで開くだけ。1つのファイルなので、USBメモリや校内の共有フォルダ、Classroom で配れます。インターネット接続は不要です。
- **PWAとして配信する場合**: このフォルダ全体を校内のWebサーバーに置き、`index.html` を開きます。一度開くと端末にキャッシュされ、オフラインでも動きます。

## 画面

| タブ | できること |
|---|---|
| 作品 | ひな形から作る（6種）、作品の一覧・複製・削除、ファイルに保存（.json）／読み込み、作品だけが動くHTMLの書き出し、企画・改善メモ（だれが使う／どんな問題／工夫／確かめ方／改善したこと）、いまの作品に server の命令が入っているかの表示（作品には server の命令を1つ以上入れる） |
| エディタ | パレットからブロックを入れる（クリックで「▶ ここに追加されます」の位置へ）、⠿ をドラッグで移動、↑↓・複製・削除、元に戻す・やり直す（記録は作品ごと）。右側のテキストコードはブロックと連動し、コードを書きかえるとブロックにも反映（コードにまちがいがある間はブロックとパレットを止める）。表示は「ブロック／両方／コード／ブロック＋実行」（ブロックの横に実行画面）。パレットの「＋ ボタンを置く」などで部品も置ける |
| 実行 | 実行画面（ステージ）と「部品の配置」（ラベル・入力ボックス・ボタンの追加・並べかえ・名前と文字の変更。名前を変えるとプログラム中の名前も自動で変わる） |
| デバッグ | 1つずつ実行（ステップ実行）、続ける、一時停止、ゆっくり実行（間隔を調整）、ブレークポイント（行番号を押す）、変数ウォッチ（変わった値に色）、実行中の行・ブロックを黄色で表示、エラーは日本語で行番号と直し方のヒント付き |
| サーバー | ブラウザ内の「サーバー役」に保存された箱（アンケートの集計グラフ、ランキング表）、通信ログ（お願い＝リクエストと返事＝レスポンス）、CSV書き出し、箱やログの消去 |
| ヘルプ | ブロックとコードの対応表、命令の一覧、書き方のきまり、安全のしくみ |
| ふりかえり・記録 | 名前の入力、いまの作品のふりかえり（双方向性の工夫・使ってもらって分かったこと）、メモかふりかえりを書いた作品・作りかえた作品の一覧（サーバーの命令の有無つき）、JSON/CSV の書き出し（ほかの教材と同じ形。組と番号がないと書き出さない） |

ひな形: ボタンでカウンター／3問クイズ／アンケート集計（サーバー）／休み時間タイプ診断／計算チャレンジ（部品＋ランキング）／バグを直そう（デバッグ練習）

## 言語（JavaScript風の簡易言語）

```
let score = 0;                       // 変数
let a = choose("問題", "A", "B");    // 選ばせる（ボタン）
let n = ask("数は？");               // 入力（数字だけなら数になる）
if (a == "A") { score += 1; } else { show("ざんねん"); }
repeat (3) { show("!"); }
while (score < 10) { score += 1; }
when ("start") { setText("result", getText("name") + "さん"); }   // ボタンが押されたとき
server.save("アンケート", a);  server.count("アンケート", "A");
server.addScore("ランキング", name, score);  server.ranking("ランキング", 5);
```

命令: show, clear, ask, choose, wait, setText, getText, random, round, number, text, length, push, includes, server.save / count / list / addScore / ranking。リストの番号は 0 から（大学入学共通テストの DNCL と同じ）。

## 安全のための設計

- 生徒のプログラムは JavaScript としては実行しません。スタジオ内の小さなインタプリタ（構文木を1文ずつ評価）が実行し、使えるのは上の命令だけです。ページの部品やネットワークには触れられません（計画書の「サンドボックス化」は、この方式で満たしています）。
- 表示する文字はすべて文字として出し、HTMLとしては解釈しません。
- 無限ループは「4秒」または「200万命令」で自動停止。実行は少しずつ区切って行うので、無限ループ中も画面は固まらず「■ 停止」が効きます（ブラウザの自動テストで確認）。表示は最新300行、文字は2万文字、リストは1万個まで。
- Content-Security-Policy で外部通信を禁止（単一HTML版・書き出したHTMLとも）。ブラウザの自動テストで外部リクエスト0件を確認。
- 作品とサーバーのデータは、その端末のブラウザ（localStorage）の中だけに保存されます。書き出したHTMLを別の端末で開くと、サーバーのデータはその端末ごとになります。

## 授業での使い方の例（目安 4〜6時間）

1. ひな形「ボタンでカウンター」「3問クイズ」で、入力→処理→表示の流れとブロック⇔コードの対応をつかむ
2. 「バグを直そう」で、ステップ実行と変数ウォッチを使ったデバッグを体験する
3. 「アンケート集計」を数人で回答し、サーバー（保存・集計）と通信ログでクライアントとサーバーの役割を確かめる
4. 作品タブの「企画・改善メモ」で、だれのどんな問題を解決するかを決めて制作する
5. 友だちに使ってもらい（HTML書き出し、または同じ端末で）、感想や集計結果から改善して、改善メモに記録する

## 開発者向け

```
npm test        # 言語・ブロック変換・インタプリタ・作品データのテスト（Node.js 20以上）
npm run build   # dist/interactive-studio.html を作り直す
npm run serve   # http://localhost:8080/D-information/interactive-studio/ で確認（共通の枠 ../../shared/ を読むため、リポジトリのいちばん上から配る）
node tests/e2e.browser.cjs   # ブラウザでの自動テスト（Playwright が必要）
```

構成: `js/lang.js`（字句・構文解析）、`js/interp.js`（インタプリタと命令一覧）、`js/runner.js`（実行制御・時間制限・ステップ実行）、`js/blockmodel.js`（ブロック⇔コード変換）、`js/blocks.js`（ブロックエディタ）、`js/stage.js`（実行画面と部品）、`js/server.js`（擬似サーバー）、`js/store.js`（作品の保存・読み込み）、`js/samples.js`（ひな形）、`js/bundle.js`（1ファイル化。build と「HTMLで書き出す」で共用）、`js/app.js`（画面）。

インタプリタは計測・制御シミュレータ（I6）とは共有せず、このフォルダの中だけで完結しています。
