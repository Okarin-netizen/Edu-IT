1. 配り方と開き方

  1. ふつうは D_情報の技術_統一版.html を配り、メニューのカード「D4 情報セキュリティ体験ラボ」から開かせます（教材を開くと、上のバーに「◀ メニュー」と「D4 情報セキュリティ体験ラボ」が出ます）。この教材だけを配るときは、1つずつ配るとき/D4_情報セキュリティ体験ラボ.html(zip の中では「個別の教材/情報セキュリティ体験ラボ.html」)を使います。中身は同じです。
  2. ファイルを、校内の共有フォルダ・USBメモリ・各端末にコピーします。
  3. 生徒はそのファイルをダブルクリック（タップ）して、ブラウザ（Chrome・Edge・Safari など）で開きます。
  4. 進み具合とふりかえりは、その端末のブラウザの中に保存されます。端末を共有する場合は、授業の終わりに「ふりかえり・記録」から書き出して提出させてください。

Chromebook や iPad で共有フォルダから直接開けない場合は、Google ドライブ等からダウンロードして開くか、ソース（D-information フォルダと shared フォルダを同じ並びのまま）を校内のWebサーバーに置いて security-lab/index.html を開いてください（一度開くとオフラインでも使えます）。

表示の切りかえ

画面右上のボタンで、ふりがな・やさしい日本語のまとめ・大きな文字に切りかえられます（生徒が自分で選べます）。作業の途中で押しても、入力や選んだものは消えません。やさしい日本語のまとめは、各ページの上と、各ステップの見出しの下（「やること」）に出ます。教材集の中で開いたときは、ふりがな・大きな文字は教材集の上のバーのボタンを使います。

振り返りを隠すとき

振り返りを Google フォームなど別の方法で集めるときは、教材の中の振り返り（各モジュールの「ふりかえり」のステップ、記録の画面の振り返りの欄など）を出さないようにできます。隠したときは、ふりかえりのステップを書かなくてもモジュールが「完了」になり、進み具合にも数えません。

  • Classroom で配るとき：生徒に配る/振り返りなし/ の中の、同じ名前のファイルを配ります。中身は同じで、振り返りだけが出ません。1つずつ配るときのファイルも 振り返りなし/1つずつ配るとき/ にあります。
  • 生徒用サイトで使うとき：アドレスの最後に ?furikaeri=off を付けて開くよう、生徒に知らせます（例: https://okarin-netizen.github.io/Edu-IT/?furikaeri=off）。一度開くと、その端末で覚えています。?furikaeri=on を付けて開くと元にもどります。
  • 隠しても、それまでに書いた振り返りは消えません（記録の書き出しにもそのまま入ります）。

2. 教材の一覧(基本編・発展編)

学習指導要領（技術分野 D）の言葉にそって、5つのまとまりと「発展」に分けています。1モジュール10〜15分が目安で、導入やまとめにも使えます。⑪ ハッシュ体験だけが発展編で、①〜⑩のモジュールと理解度チェックは基本編です。画面の左のメニューも、基本編の①〜⑩のあとに「発展（先生に言われたら）」の ⑪ がならびます。分け方の理由は、先生用フォルダの 全分野_基本編と発展編.html にあります。

#モジュール主な体験目安

3. 単元での使い方

7時間の計画の例

時間内容
1時間目理解度チェック「事前テスト」（5分）→ ① デジタル化と情報量
2時間目② パスワード強度ラボ → ③ 暗号ラボ（前半）
3時間目③ 暗号ラボ（後半）→（発展）⑪ ハッシュ体験
4時間目④ フィッシング見分け → ⑤ ネットワーク通信の模擬
5時間目⑥ SNS投稿の個人情報チェック → ⑦ デジタルタトゥー
6時間目⑧ 著作権・利用ルールクイズ → ⑨ 判断ロールプレイ
7時間目⑩ まとめ・行動宣言 → 「事後テスト」→ 記録の書き出し・提出

時間が限られる場合は、先生用ページの「設定」で使うモジュールをしぼれます。デジタル化ラボとネットワーク通信シミュレータを先に使った場合は、「① デジタル化と情報量」と「⑤ ネットワーク通信の模擬」を省いて5時間にできます。⑪ ハッシュ体験は発展なので、3時間目に暗号ラボの後半だけを行ってもかまいません（情報の技術の先生用ガイドの 3.「内容が重なっている単元」）。ふりかえりをペアやグループで紹介し合うと、理解が深まります。行動宣言カードは家庭に持ち帰らせるのもおすすめです。

4. 記録の保存と提出

提出と集計

  1. 生徒は「ふりかえり・記録」でクラス（組）・出席番号（設定により名前）を入力し、「JSONで書き出す」を押します。組か番号が空のときは「組と番号を入れてから書き出そう」と出て、書き出しません。書き出すと、画面にファイル名が出ます。できたファイルを、Google Classroom や共有フォルダで提出させます（画面にも「先生に出すのは JSON のファイルです」と書いてあります。CSV は生徒が自分で見るためのものです）。「JSONから読み込む」で今の記録が置きかわるときは、確認が出ます。教材集の中で使うときは、メニューの「記録をまとめて書き出す」でも、ほかの教材といっしょに書き出せます。
  2. 先生は「先生用ページ」の「クラスの記録を集計する」で、提出された JSON ファイルをまとめて選びます。モジュールごとの完了人数、ふりかえりの記入人数、事前・事後テストの平均正答率と、両方を受けた生徒だけでくらべた伸びが表示されます。設定で外したモジュールでも、記録があれば書き出しに入ります。
  3. 「まとめてCSVで保存」を押すと、Excel で開ける一覧表（ふりかえりの文章も含む）ができます。
  4. ほかの分野と同じように、4分野共通の 全分野_振り返り一覧.html でふりかえりを一覧にすることもできます。

理解度チェック（事前・事後テスト）

  • 事前テスト・事後テストは、どちらも1回目の点が記録になります。2回目からは「練習」として採点し、記録は変わりません。
  • 事前テストのあとは、答えと解説を見せません（点だけ出ます）。事後テストが終わると、答えと解説が見られます。事後テストが終わるまでは、練習・復習にも事前・事後テストと同じ問題は出ません。
  • 「練習」は、生徒がモジュールにチェックを入れてから始めます（はじめはどれも選んでいません）。1回に10問までで、毎回ちがう問題が出ます。事前・事後テストの問題は、章の順（① デジタル化が第1問、⑪ ハッシュ体験の問題は最後）にならびます。
  • 事前テストを受けずに事後テストを押すと、「事前テストがまだです」と出て、先に事前テストをするか選べます。

判断ロールプレイの記録

ストーリーごとに「最初に選んだ結末」と「いちばんよかった結末」の2つが記録に入ります（CSV のスコア欄では、ストーリーのid（例 dm=bad）が最初の結末、_best の付いたもの（例 dm_best=good）がいちばんよかった結末です。good＝安全、ok＝途中で気づけた、bad＝危ない）。生徒の画面には「先生は、クラスでどんな選び方が多かったかを見るために使います。成績にはしません。」と出ています。

パスワード強度ラボ・ハッシュ体験で入力した文字は、保存も書き出しもされません。授業では「本物のパスワードは入力しない」と必ず声をかけてください（画面にも表示されます）。

先生用ページの開き方

先生用ページは、生徒の章ナビには出ません。ブラウザのアドレスの最後に次の文字を足して開きます。

  • 教材集で開くとき: D_情報の技術_統一版.html#/security-lab/teacher
  • 1つだけ配るファイルで開くとき: D4_情報セキュリティ体験ラボ.html#/teacher（Webサーバーなら …/security-lab/index.html#/teacher）

設定と問題の差し替え

  • 設定：先生用ページで、使うモジュール、表示の初期値、名前を入力させるか、パスワード強度ラボの攻撃速度の初期値を変えられます。「この端末に反映」はその端末だけで、押すと確認が出ます。「標準に戻す」で、その端末の設定をはじめの状態にもどせます。「設定ファイルを書き出す」でできた config.json は、ソースの data フォルダに置くと配布するすべての端末に反映できます。
  • 相談窓口：デジタルタトゥー・判断ロールプレイ・まとめ・行動宣言に、相談窓口（24時間こどもSOSダイヤル、子どもの人権110番、警察相談専用電話 #9110）と「学校の先生や家の人にも相談しよう」が出ます。番号は 2026年10月13日に公式ページで確かめました。年度ごとに確かめて、consult.json を直してください（学校の相談室や市の窓口も足せます）。先生用ページの「問題データを差し替える」でも変えられます。
  • 問題の差し替え：フィッシングの場面、理解度チェックの問題、著作権クイズ、ロールプレイのストーリーなどは JSON ファイルです。先生用ページで「今のデータを書き出す」→ 編集 →「読み込んで差し替える」で、その端末の問題を変えられます。
  • 単一HTMLファイルに変更を組み込み直すには、ソースフォルダ（D-information/security-lab）で node tools/build-standalone.mjs を実行します（Node.js が必要）。

5. 授業で使うときの注意

  • 攻撃の方法を教えるのではなく、「しくみを知って、判断の手順を身につける」ことがねらいです。実際に攻撃できるツールは含まれていません。RSA や通信の暗号は、しくみを見せるための小さな模型です。
  • ⑧ 著作権・利用ルールクイズの解説（私的使用、引用、授業での利用〔著作権法第35条・第38条〕など）は中学生向けに簡単にしています。私的使用については、「違法にアップロードされたものと知りながらダウンロードすること」「コピーガード（技術的保護手段）を外してコピーすること」は認められない（著作権法第30条）ことを、まとめと解説に書いています。海賊版サイトのマンガ・アニメなど身近な例で補足してください。
  • ① デジタル化と情報量の音の体験では、端末から音が出ます。イヤホンの使用や音量に配慮してください。
  • ネットのトラブルを経験している生徒もいます。「困ったら一人でかかえこまず相談する」ことを、くり返し伝えてください。

6. こまったとき

どの端末・ブラウザで動くか
Chrome・Edge・Safari・Firefox の最近の版で動作します（Windows・Chromebook・iPad・Mac）。インターネット接続は不要です。
Chromebook や iPad で開くと動かない
Google ドライブの画面や「ファイル」アプリで開くと「プレビュー」になることがあります。端末にダウンロードしてから開くか、校内のWebサーバーに置いて開いてください（1. を見てください）。
記録が消えた
記録はブラウザに保存されるため、ブラウザの履歴やデータを消すと記録も消えます。別の端末・別のブラウザで開いたときも見えません。大切な記録は、授業の終わりに書き出させてください。
先生用ページが開かない
アドレスに # から後ろがすでに付いているときは、それを消してから #/teacher(教材集では #/security-lab/teacher)を足します。
使わないはずのモジュールが出る・出ない
設定は「この端末に反映」した端末だけにかかります。先生用ページの「標準に戻す」で、その端末の設定をはじめの状態にもどせます。
