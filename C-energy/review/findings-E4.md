# E4「保守点検ラボ」レビュー結果

**良い点:** 図鑑 → 機械を見る → 不具合事例クイズ → ゆるみ・摩耗シミュ → 点検表づくり、という流れがよくまとまっている。どのクイズの選択肢にも理由が付き、「電源を切る・止まってから・大人と」という安全の注意も各所に入っていて、「なぜ点検が要るのか」を体験しやすい。コンソールエラーは0件。JSON保存・読込と印刷も基本の動作は正常。
**一番の問題:** ①点検項目を消すと、過去の点検記録の ⭕🔺❌ が別の項目にずれる(印刷にもずれたまま出る)。②部品あてクイズで正解が1つに決まらない問題が出る。③縦向きの「機械を見る」は図が小さく、?印が約31pxしかないうえ、見つけた部品の名前が重なる。
**難易度:** ルビがない(摩耗・潤滑・従動節・揺動 などに読みがない)のと、正しい選択肢がほぼ必ず「一番長い文」になっている点が大きな課題。

確認環境: Playwright(Chromium)、横 1180×820 / 縦 820×1180、hasTouch・isMobile、タップで操作。

## A(誤り・不具合・学習の妨げ)

**A1 [不具合] 点検項目を消すと、点検記録の結果が別の項目にずれる**
- 場所: 📋点検表づくり。`index.html:1938`(`cdel`)、`index.html:1726-1731`(`toggleCand` で候補を外したとき)
- 問題: `L.items` からは項目を消すが、各記録の `records[].res` 配列からは消していない(▲で並べかえる `cup` は記録も入れかえている)。記録「ブレーキ=⭕ / タイヤ=🔺 / チェーン=❌ / ねじ=⭕」のあとでブレーキを消すと「タイヤ=⭕ / チェーン=🔺 / ねじ=❌」になった。印刷・記録一覧・保存JSONにもずれたまま出る。
- 直し方: `cdel` と `toggleCand` で項目を消すとき `L.records.forEach(r => r.res.splice(at,1))` も行う。記録が1件以上ある点検表では「記録の列も消えます」と確認を出す。

**A2 [内容/難易度] 部品あてクイズで、正解が1つに決まらない問題が出る**
- 場所: ❓クイズ › 部品あて。`makePartQs` / `blankName`(`index.html:1295-1311`)
- 問題: 問題文は部品データの「使われている所」と「点検」から自動で作られるため、ほかの選択肢も当てはまる問題ができる。例: スプロケット「自転車、オートバイ / チェーンのたるみ」でチェーンも正しい。プーリー「ベルトがゆるんでいないか」で平ベルトも自然。送りねじ「□□山のつぶれ・油切れ・ゆるみ」でボルトとナットも正しい。ラック「歯の摩耗・油切れ」は歯車・スプロケットと区別できない。軸受「異音・ガタ/油切れ」、軸「曲がり/ガタつき」も同様。逆に「玉□□(ボールベアリング)」「4本の棒(リンク)…」のように答えが見える問題もある。
- 直し方: 部品ごとに区別できる手がかりを手で書いた問題文を用意する。最低限、まぎらわしい組(chain⇔sprocket、pulley⇔belt、bolt⇔screw、gear⇔rack⇔sprocket)がいっしょに選択肢に入らない除外表を作る。伏せ字はかっこ内の別名(ベアリング・リンクなど)も対象にする。

**A3 [内容] 軸継手の「使われている所」に「扇風機のモーターと羽根(押さえナット)」が入っている**
- 場所: `index.html:481`(E4data `EXTRA.coupling.where`)
- 問題: 押さえナットは羽根を軸に留めるナットで、軸継手ではない。同じアプリの「機械を見る」では押さえナットは「ボルト・ナット」に分類(`index.html:938`)。
- 直し方: 削除し、「電動ポンプ」「ボール盤の主軸(モーターとの間)」など本当に使われる例にする。

**A4 [内容] 平ベルトの「使われている所」に「扇風機の首ふり部」が入っている(機構コアの部品データ。E3も同じコア)**
- 場所: `index.html:216`(mech-core `PARTS.belt.where`)
- 問題: 扇風機の首ふりはふつうウォームギヤとリンクで動く。このアプリの「機械を見る › 扇風機」もそう説明している(`index.html:941-942`)。
- 直し方: 「扇風機の首ふり部」を削除し、「ボール盤」「洗濯機」「農業機械」などに。E3/E4/mech-core.js の3か所を同じに直す。

**A5 [表示/操作] 「機械を見る」: 縦向きで図が小さく、?印が約31px。見つけた部品のラベルも重なる(横向きでも重なる)**
- 場所: `.e4-side{width:330px}` / `@media(max-width:1100px){.e4-side{width:290px}}`(`index.html:34,165`)、`renderMach`(`index.html:1154-1172`)、ラベル(`index.html:1165`)、扇風機の印の座標(`index.html:938-940`)
- 問題: 縦向きでも右に固定幅290pxのパネルが並び、図の領域は530px幅で上下に大きな空白。?の丸は直径31px(横向き50px)。ラベルは縦向きで約12px。扇風機の「押さえナット」「モーターの軸」「軸受」は中心が64〜70単位しか離れておらずラベルが重なる(横向きでも)。自転車でも「ハンドルの軸受」と「サドルの固定ボルト」などが重なる。
- 直し方: 縦向きではサイドパネルを図の下に回し図を幅いっぱいに。?の丸を r=40 程度に。扇風機の3点は間隔をとり、ラベルは上下に交互にずらすか引き出し線を付ける。

**A6 [学習の妨げ] 事例クイズで「よく調べる」を押さずに原因を答えられ、手がかりなしでは判別できない問題で×になる**
- 場所: `renderCaseQ`(`index.html:1253-1255`)、CASES の clue
- 問題: 「チェーンがよく外れる」(歯の欠け⇔たるみ)、「前輪がゴリゴリ」(ブレーキのこすれ⇔軸受)、「扇風機がキーキー」(押さえナット⇔軸受)は症状だけで見分けられない。×のあとの理由に「今回は歯は欠けていない」など、まだ見ていない情報が出る。
- 直し方: 「🔍 よく調べる」を押すまで原因の選択肢を無効にし「まず調べよう」と表示する。

**A7 [表示] 縦向きの「チェーンのたるみ」アニメで、前のスプロケットが左にはみ出して切れる**
- 場所: `drawChain` の `k = Math.min(1.2, H/260)`(`index.html:1634`)
- 直し方: `k = Math.min(1.2, H/260, W/520)` のように幅も考える。`drawBolt` / `drawBear` も同様。

## B(わかりにくい・難しすぎる)

**B1 [難易度] ルビがなく、難しい語に読みも説明もない(一部は機構コアの部品データ。E3と共通)**
- 摩耗・潤滑・摩擦・振動・増しじめ・焼き付き・被覆・含油軸受(`:940`)・主軸・逆ねじ・半断線・トラッキング現象・ブシュ(`:507`)。mech-core 側: 従動節(`:230`)・揺動(`:233`)・リード/ピッチ/条数(`:239`)。タブ名「摩耗」にも読みがない。
- 直し方: 初出にふりがなと短い説明(例: 揺動=行ったり来たりする回転、従動節=カムに押されて動く棒)。「条数」は中学範囲外なので外し「1回転でねじ山1つ分(ピッチ)進む」程度に。

**B2 [難易度] 正しい選択肢がほぼ必ず一番長い文**
- 場所: CASES 全15問(`index.html:656-867`)。対処の正解は15問中15問、原因の正解は15問中13問が最長。誤答に「テレビの電気料金が高すぎる」「洗剤の入れすぎ」など明らかに無関係なものが多い。
- 直し方: 誤答も同じくらいの長さ・具体性で書く(例:「チェーンの油を拭き取り、乾いた状態で使う」「後輪のナットだけを強くしめ直す」)。無関係な誤答は「もっともらしいが違う」原因に差しかえる。

**B3 [内容] 「含油軸受が多い」と書きながら、扇風機の事例の正解が「指定の油を差す」**
- 場所: `index.html:940`、`index.html:736`(fan-squeak)
- 問題: 家庭用扇風機は説明書で「注油不要」とされるものが多く、生徒が家で潤滑剤を吹き付けるおそれ。
- 直し方: 正解を「プラグを抜き、説明書を確認する。注油の指示がある場合だけ指定の油を差す。指示がない・直らないときは販売店へ」に。理由に「含油軸受は油を含ませてあり、ふつうは注油しない」を加える。

**B4 [内容] 「へたり=伸びたまま」という一般化**(`:486`、`:510`) 圧縮ばねは縮むほうにへたる。「へたり(長さや力がもとにもどらなくなる)」と書く。

**B5 [内容/操作] ゆるみシミュ「しめる強さ: 弱い」で、点検のたびに「しめ直した」と出るのにゆるんだまま**(`:1353,1361`) 1年比較で「直した52回」になる。点検でしめ直したら100%にもどし、「弱い」は最初の状態だけの条件にする(または画面に「しめ直しても弱いまま」と書く)。

**B6 [内容] チェーンシミュの「ちょうどよい」判定が目安(10〜20mm)と合わない**(`:1400` `warn: s>22`、`:1408`) 21.5mm で「ちょうどよい」。しきい値を20mmにそろえる(warn・inspect・sign・グラフの注意ゾーン)。

**B7 [操作] 点検表がないと「ファイルを読み込む」が出ない。保存・読込をしても画面に何も出ない**(`:1663-1667`、`saveJSON :1828-1837`、`applyImport :1857`) 点検表がない画面にも「📂 ファイルを読み込む」を置く。点検表画面にメッセージ帯かトースト(「保存しました(ファイル名)」「読み込みました」)を出す。

**B8 [操作] 印刷の点検表に手書き用の空欄列がない**(`printList :1813-1819`) 記録が1回あるとその1列だけになる。記録の列のあとに合計5〜6列になるよう空欄の「月/日」列を足す。

**B9 [操作] 元に戻せない操作が確認なしで実行される** 点検項目の「✕」(`:1682,1938`、46×40pxで▲の6px隣)、「↺ 印をもどす」(`:1160,1907`)、シミュの「↺」(`:1462`)。消したら「元に戻す」付き通知か確認を出す。✕は▲から離して右端に。

**B10 [操作] クイズの途中でタブを押すと進行が消える**(`:1894` で `S.qz=null`)、クイズ中の図鑑モーダルの事例ボタン(`:1088,1914`)で別の1問クイズに置きかわる。タブ移動しても `S.qz` を残し、クイズ中の図鑑モーダルでは事例・機械へのボタンを隠す。

**B11 [表示] 14px未満の文字が多い** 図鑑カード 読み12px・バッジ12px・説明13px(`:57-59`)、クイズカード13px(`:85,87`)、機械バー13px(`:41`)、点検表13px(`:138`)、記録ボタンの「よい/気になる/だめ」11px(`:1789`)、グラフ12〜13px(`:1533,1542`)、合いマーク説明13px(`:1598`)。図鑑カードの説明は2行で「…」と切れる(横向きで17枚中10枚)。本文15px以上・読み13px以上にし、カードには短い1文の要約を別に用意する。

**B12 [操作] タッチ目標が44px未満(40〜42px)** チップ(42px、`:43`)、`.e4-btn.sm`(40px、`:29`)、点検表の方法・間隔チップ(40px、`:139`)。最小44pxに。▲と✕は間隔も広げる。

**B13 [内容] 教科書の基本用語が足りない** 「転がり軸受・滑り軸受」「平座金」「小ねじ・木ねじ」が図鑑にない。ボール盤の事例(`:855-857`)に出る「Vベルト」が図鑑にない。軸受カードに転がり/滑り、ボルト・ナットに平座金・小ねじ・木ねじ、平ベルトに「Vベルト(断面がV字で、すべりにくい)」を加える。

## C(表記ゆれ・細部)

- C1 [一貫性] 「締めすぎる」(`:495`)と「しめる」、「点検の周期」(`:1480,1498`)と「点検する間隔」(`:877`)、「前の歯車(スプロケット)」、ベルトがすべる2事例で関連部品が「プーリー」(`:853`)と「平ベルト」(`:797`)に分かれる。
- C2 [難易度] 読みの出し方が不自然: プーリー(ベルト車)→「ぷーりー」、「ねじ(送りねじ)」→「ねじ」、「スライダクランク機構」→「すらいだくらんく」。漢字部分の読み(べるとぐるま、おくりねじ、きこう)を示す。
- C3 [内容] 不自然な誤答: 「材料のボルトのゆるみ」(`:859`)、「スイッチの歯車の欠け」(`:776`)、「テレビの電気料金が高すぎる」(`:790`)。「軸のナットを力いっぱいしめる」(`:710`)は「無理にしめると部品が傷む」でよい。
- C4 [内容] 点検になっていない点検ポイント(機構コア。E3と共通): クランクの「潤滑」(`:237`)、チェーンの「油を差す」(`:219`)。「油が切れていないか」「たるみが10〜20mmか」の形に。
- C5 [内容] ペダル事例の正解「スパナでしめ直す」(`:694`)に「大人と」を加える。左ペダル逆ねじの説明は「ゆるむ向きの力がかからないように」程度に。
- C6 [表示] ゆるみ止めアイコンの「2つ」が約9pxで意味不明(`:558`)。「ダブルナット」にするか削除。
- C7 [一貫性] 幅1100px以下でヘッダーのアプリ名が消える(`:165`)。
- C8 [操作] 点検表一覧で同じ名前が並び区別できない(作成日・項目数を表示)。▼(下へ)がない。
- C9 [内容] アドバイスの★が甘い(`:1767`)。未設定がある間は★1に。
- C10 [操作] 図鑑の「🚲 自転車で見る」で部品が自動で「見つけた」扱いになる(`:1902`)。機械の?をタップしただけで図鑑の「✔ 見た」が付く(`:1194`)。
- C11 [一貫性] 分類バッジ色(`#b5541c`)が主ボタンのオレンジ(`#c8620e`)とほぼ同じ。
- C12 [操作] 効果音が初期ON(`:1008`)。授業で30台が同時に鳴る。
- C13 [計画との差] PWA未実装、保存は localStorage。

## 他アプリ比較用のUI事実

- ヘッダー: #2f4858・58px。アプリ名「🔧 保守点検ラボ」(幅1100px以下で非表示)、タブ5つ(選択中は白地)、右端に「❔」(文字なし、aria-label「使い方」)と「🔊/🔇」(初期ON)。
- 使い方: 初回自動表示、閉じる「わかった」。
- モーダルの閉じる文言: 図鑑詳細・一覧・エラー・記録を見る「とじる」、記録入力「やめる」/「記録する」、クイズ結果「クイズのはじめへ」。×なし、背景タップ・Escで閉じる。
- 主ボタン: オレンジ #c8620e、副は青 #1e6fd9、削除は薄い赤、点検は薄い緑、選択中は紺。
- クイズ: 事例は「🔍 よく調べる」(任意)→原因4択→対処3択→「⚠ 安全」「💡 学び」→「次の問題へ ▶」。結果「📝 結果」/「🎉 全問正解!」。部品あて10問4択。正解は緑+⭕+2音。
- 保存・印刷: 「🖨️ 印刷」「💾 ファイルに保存」「📂 ファイルを読み込む」。保存後の画面表示なし。
- メッセージ帯: 「機械を見る」「ゆるみ・摩耗」だけ。
- ルビ: なし(図鑑カードに小さいひらがなの読み行のみ)。
