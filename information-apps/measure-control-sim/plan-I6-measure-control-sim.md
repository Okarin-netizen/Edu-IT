# 実装計画 I6「計測・制御シミュレータ」

## 1. 概要
- **教科書・指導要領との対応**: 情報の技術『計測・制御のプログラミングによる問題解決』。指導要領 D(3)『入出力されるデータの流れを元に計測・制御システムを構想して情報処理の手順を具体化』
- **ねらい**: センサ(計測)の値に応じてアクチュエータ(制御)を動かす仕組みを、プログラムで設計・検証する。実機がなくても学習が成り立つようにする。
- **形態**: PWA(Service Worker+IndexedDB)の単一Webアプリ。外部通信なし、オフライン完結。共通基盤は [README.md](README.md) を参照。
- **関連**: I5、I2、X4

## 2. 機能要件
### MVP
1. 仮想マイコン+センサ(明るさ・温度・距離・ボタン・人感)・出力(LED・ブザー・モーター・サーボ・表示)
2. シナリオ(背景・状況つき): 自動ドア、街灯、信号機、見守り、エアコン、水やり、障害物回避ロボ
3. プログラミング: フローチャート ⇔ ブロック ⇔ 簡易テキスト言語の相互変換
4. 仮想世界: 環境値(明るさ・気温など)をスライダやタイムラインで変化させ、動作を確認
5. デバッグ: ステップ実行、変数/センサ値のグラフ表示、ログ
6. 評価: 想定ケースのテスト(合格/不合格)の自動判定と、改善記録
### 発展
- 複数センサ・状態機械(ステート)の設計
- 実機への書き出し(micro:bit等 Web Serial/WebUSB、オンライン不要)
- ログの時系列保存と分析

## 3. 技術設計
- 時間駆動のシミュレーションループ(固定刻み)
- プログラム実行系は I5/I2 と共通化(インタプリタ)
- シナリオはJSON(センサ入力の時系列・合否判定ルール)
- 描画はCanvas/SVGのイラスト(自作)

## 4. 画面構成
- シナリオ選択 / エディタ(フロー・ブロック) / 仮想世界 / デバッグ・テスト

## 5. 受け入れ基準・テスト
- 代表シナリオで『模範プログラム』が全テストに合格する
- 無限ループ・並列実行の暴走を防ぐ
- オフラインで全機能が動作

## 6. リスクと対策
- 教科書の教材(実機)との違い → 実機と併用する前提。変換機能で橋渡し

## 7. 工数目安
約4〜5週間(MVPは自動ドア・信号・街灯の3シナリオなら約3週間)
