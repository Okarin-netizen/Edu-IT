# 教材集のメニューと、6教材に共通すること 中学生目線レビュー

> **この記録について**: 2026-10-13 に、教材集 第1版（情報の技術_体験教材集.html）の中でこの教材を中学生の立場で操作して書いたレビューの記録です。「画面例」のリンクから、その時の画面を開けます。.cjs・.mjs・work/… は、レビューのときに使った確認用のスクリプトと記録で、このフォルダには入れていません。各指摘の「改善計画」は、まとめの文書の段階（第1段〜第3段）を示します。教材のファイルはまだ書きかえていません。

対象: 教材集 `/mnt/project-files/kyozai-shu/release/情報の技術_体験教材集.html` のメニュー・上のバー・教材の切りかえと、6教材をくらべて分かったそろっていない点。
画面は Playwright（Chromium）で、ノートPC 1366×650、タブレット横 1080×810・縦 810×1080（指で操作）で開いた。

## 1. ひとことで
- メニューは「はじめての人は、ここから」「おすすめの順番」「前回のつづき」があり、中学生が最初に迷うことは少ない。切りかえても作業が残ること、記録をまとめて消せること（確認つき）もよい。
- 一方で、6教材を通して使うと「ふりがな・大きな文字があったりなかったりする」「記録のページの言葉や名前の入れ方がちがう」「タブレット縦では左のメニューが横1列になり、いまどこにいるかが見えない」の3つが目立つ。
- いちばん大事な指摘: **KS-01**、**KS-02**、**KS-05**

## 2. 通しで体験した記録
| 画面 | 生徒としてやったこと | つまずいたところ |
|---|---|---|
| メニュー（#/） | 4つの画面の大きさで開いた。「はじめての人は、ここから」から1番を開き、メニューにもどって2番以降も開いた | ノートPCでも「はじめての人は、ここから」までが最初の画面に入る（問題なし） |
| 上のバー（教材を開いたとき） | アイコンでほかの教材に切りかえ、左の名前でメニューにもどった | アイコンだけで名前が出ない（KS-04）。上のバー2本で縦がせまい（KS-03） |
| 6教材の「ふりかえり・記録」 | 名前の欄、書き出しのボタン、消すボタンをくらべた | 言葉と項目が教材ごとにちがう（KS-05） |
| タブレット縦の左のメニュー | セキュリティラボのモジュール9を開いた | メニューの帯に、いまのページ（9）が見えない（KS-02） |

## 3. 指摘一覧

### KS-01 ふりがな・やさしい日本語・大きな文字が、教材によってあったりなかったりする
- 改善計画: 第2段・2-3「読むのが苦手な生徒への手当て」
- 場所: 6教材の上のバー
- 観点: 配慮 / 難易度
- 重要度: B
- 確信度: 確認済み
- 中学生の声: 「セキュリティラボはふりがなが出たのに、デジタル化ラボにはボタンがない。ひょうほんか？」（Aさん）
- 何が起きているか:
  - 「ふりがな」「やさしい日本語」は情報セキュリティ体験ラボだけ。「大きな文字」はデジタル化ラボ・ネットワーク通信シミュレータ・情報セキュリティ体験ラボ・計測・制御シミュレータの4つで、仮想CPUラボと双方向コンテンツ制作スタジオにはない。
  - デジタル化ラボ・ネットワーク通信シミュレータの README には「ふりがな・やさしい日本語の表示」が「これから足せるもの」として残っている。
  - セキュリティラボのふりがなは、言葉と読みの一覧（data/ruby.json、194語）をもとに、画面の文字にあとからふりがなを付けるしくみで、ほかの教材にも使い回せる作り。
- 根拠: 6教材の上のバーの文字（教材集の中で取得）、/mnt/project-files/security-lab/js/settings.js:88-105、/mnt/project-files/security-lab/data/ruby.json、/mnt/project-files/digitization-lab/README.md:45、/mnt/project-files/network-sim/README.md:44
- 改善案:
  - 教材集の上のバーに「ふりがな」「大きな文字」を1つずつ置き、6教材すべてにかかるようにする（セキュリティラボのしくみを教材集に移し、6教材の用語を足した共通の一覧を使う）。プログラムを書く欄や図の中の文字にはふりがなを付けない。
  - 「やさしい日本語」は、まず各単元の最初に「やさしい日本語のまとめ」を1つずつ置く形で広げる（セキュリティラボと同じ形）。
- 手間: 中（教材集のしくみ＋共通の言葉の一覧）〜大（6教材すべてにやさしい日本語の文）
- ほかの教材にも: あり（DL-07、NW-13、ほか各教材の担当も指摘）

### KS-02 タブレット縦（横はば860px未満）では、左のメニューが横1列の帯になり、いまのページや後ろの単元が見えない

- 観点: 操作
- 重要度: B
- 確信度: 確認済み

  - モジュール9を開いても、帯は左はしのままで、いまのページ（9）は画面の外（x＝1,629〜1,861px）にある。
  - 双方向コンテンツ制作スタジオでは「ふりかえり・記」で切れる。6教材とも同じ作り。
- 根拠: [inside-sec-tabletPortrait.png](/mnt/project-files/reviews/2026-10-13_中学生目線レビュー/画面例/00_教材集/inside-sec-tabletPortrait.png)、[strip-sec-portrait-module9.png](/mnt/project-files/reviews/2026-10-13_中学生目線レビュー/画面例/00_教材集/strip-sec-portrait-module9.png)、[inside-is-tabletPortrait.png](/mnt/project-files/reviews/2026-10-13_中学生目線レビュー/画面例/00_教材集/inside-is-tabletPortrait.png)、/mnt/project-files/security-lab/css/style.css:139-141（ほかの5教材も同じ行）
- 改善案:
  - 帯をやめて、860px未満では2〜3列に折り返す（または「メニュー ▾」で開く一覧にする）。
  - 帯のままにするなら、いまのページを帯のまん中に自動でスクロールし、右はしに「→ まだあります」の印（うすくなる影）を付ける。
- 手間: 小（CSSと数行のスクリプト。6教材共通なので教材集の assist.css でも直せる）
- ほかの教材にも: あり（6教材すべて）

### KS-03 教材を開くと上のバーが2本になり、ノートPCでは使える高さが約8割になる
- 改善計画: 第2段・2-1「ノートPCの画面に収める」
- 場所: 教材を開いたときの画面（教材集のバー52px＋教材のバー約55px）
- 観点: 操作
- 重要度: C
- 確信度: 確認済み
- 中学生の声: 「図とボタンと結果が1画面に入らなくて、上と下を行ったり来たりする」（Bさん）
- 何が起きているか: 1366×768 のノートPC（ブラウザの中は約650px）では、2本のバーで約107pxを使い、教材に使える高さは約543px。教材のバーはスクロールしても上に残る。図と結果を同時に見たい教材（ネットワーク通信シミュレータ、仮想CPUラボ、計測・制御シミュレータ）で、結果が画面の外に出る原因の1つになっている（NW-04）。タブレット縦では教材のバーが2段になり、約147pxになる。
- 根拠: [inside-is-laptop.png](/mnt/project-files/reviews/2026-10-13_中学生目線レビュー/画面例/00_教材集/inside-is-laptop.png)、[inside-sec-tabletPortrait.png](/mnt/project-files/reviews/2026-10-13_中学生目線レビュー/画面例/00_教材集/inside-sec-tabletPortrait.png)、/mnt/project-files/kyozai-shu/src/shell.css:148、各教材 css/style.css:110（教材のバーが sticky）
- 改善案: 教材集の中では、教材集のバーを細くする（40px）か、教材のバーの右はしに教材集のアイコンをまとめて1本にする。または、下へスクロールしたら教材集のバーをかくす。
- 手間: 小〜中
- ほかの教材にも: あり（6教材すべて）

### KS-04 教材を切りかえるアイコンに名前が出ず、タブレットではどれが何か分からない
- 改善計画: 第2段・2-2「タブレットで使いやすく」

- 観点: 操作
- 重要度: C

### KS-05 「ふりかえり・記録」の言葉と項目が教材ごとにちがい、名前を6回入れて、6つのファイルを出すことになる
- 改善計画: 第2段・2-7「記録と提出をそろえる」
- 場所: 6教材の「ふりかえり・記録」
- 観点: 操作
- 重要度: B
- 確信度: 確認済み
- 中学生の声: 「さっきも名前入れたのに、また？ 6個もファイルを出すの？」（Bさん）／（先生）「35人×6教材＝210ファイル…」
- 何が起きているか:
  - 名前の欄: 5教材は「組・番号・名前」、情報セキュリティ体験ラボだけ「クラス・出席番号・名前（任意）」。
  - 書き出すボタン: 「JSONで書き出す」「記録を書き出す（JSON）」、「CSVで書き出す（表計算ソフト用）」「CSVで書き出す」が混ざる。
  - 消すボタン: 「この端末の記録を消す」「この端末の記録をすべて消す」「記録をすべて消す」が混ざる。
  - 名前は教材ごとに別に保存されるので、6教材を使う生徒は名前を6回入れ、記録のファイルも6つ出す。名前が空のまま書き出せる教材もある（DL-15）。
- 根拠: [records-digitization-lab.png](/mnt/project-files/reviews/2026-10-13_中学生目線レビュー/画面例/00_教材集/records-digitization-lab.png)、[records-security-lab.png](/mnt/project-files/reviews/2026-10-13_中学生目線レビュー/画面例/00_教材集/records-security-lab.png) など6枚、/mnt/project-files/kyozai-shu/data/materials.json（resetKeys で教材ごとに別のキー）
- 改善案:
  - 6教材の言葉をそろえる（例:「組・番号・名前」「JSONで書き出す（先生に出す）」「CSVで書き出す（表計算ソフト用）」「この端末の記録をすべて消す」）。
  - 教材集のメニューに「名前を入れる」欄を1つ置き、6教材の名前の欄に自動で入れる。
  - 教材集のメニューに「6教材の記録をまとめて書き出す」ボタンを置き、1つのファイル（または1つのCSV）にする。
- 手間: 小（言葉をそろえる）〜中（名前をまとめる・まとめて書き出す）
- ほかの教材にも: あり（6教材すべて）

### KS-06 入力の受け付け方とふりかえりの保存のしかたが、教材ごとにちがう
- 改善計画: 第1段・1-A「作業を消さない」
- 場所: 6教材の入力欄とふりかえりの欄
- 観点: 操作
- 重要度: B
- 確信度: 確認済み（各教材の担当の指摘をまとめたもの）
- 中学生の声: 「仮想CPUでは全角でも通ったのに、デジタル化ラボでは『まちがい』になった」（Bさん）／「書いたふりかえりが消えた」（Aさん）
- 何が起きているか:
  - 全角の数字・英字: 仮想CPUラボは半角に直して受け付けるが、デジタル化ラボ・ネットワーク通信シミュレータは「まちがい」にする（DL-02、NW-09）。
  - ふりかえり: デジタル化ラボ・ネットワーク通信シミュレータ・情報セキュリティ体験ラボは「保存」を押さないと消える（DL-06、NW-06）。
  - 追記: その後のレビューで、仮想CPUラボ・計測・制御シミュレータ・双方向コンテンツ制作スタジオも同じだと分かった（CPU-02、MC-07、IS-10、SEC-52）。6教材すべてで、保存を押さないと消える。
- 根拠: /mnt/project-files/virtual-cpu/js/auto.js:53（全角を半角に直す）、/mnt/project-files/digitization-lab/js/ui.js:62-89、/mnt/project-files/network-sim/js/ui.js:63-90、/mnt/project-files/security-lab/js/ui.js:73-90
- 改善案: 6教材で同じ決まりにする。①答えの欄はすべて全角→半角に直してから判定する、②ふりかえりは入力のたびに下書きを自動で保存する。共通の部品（js/ui.js）を直して、6教材に入れる。
- 手間: 小〜中
- ほかの教材にも: あり（6教材すべて）

### KS-07 iPad で使えるかを確かめたい（先生用の手引きには「タップして Safari などで開く」とある）
- 改善計画: 第1段・1-E「案内と配り方」
- 場所: 先生用の手引き「1. 使い方」、配り方
- 観点: 操作
- 重要度: B（iPad の学校のとき）
- 確信度: 推定（実機では確かめていない）
- 中学生の声: 「ファイルを開いたけど、文字だけ出て何も押せない」（iPad のBさん）
- 何が起きているか:
  - 手引きには「ダブルクリック（タップ）して、ブラウザ（Edge・Chrome・Safari など）で開きます」とある。
  - iPad の「ファイル」アプリで HTML を開くと、ふつうはプレビュー表示になり、JavaScript で動く教材は動かないことが多い。Edge なども、端末の中の HTML ファイルを開くときは制限がある（Microsoft の回答ページ）。
  - iPad の Safari では、https のページでないとマイクも使えない（DL-08）。
- 根拠: /mnt/project-files/kyozai-shu/docs/先生用の手引き.html（1. 使い方）、[Microsoft Q&A: iPad の Edge でローカル HTML を開く](https://learn.microsoft.com/en-au/answers/questions/2007275/how-can-i-make-edge-open-a-local-html-file-on-an-i)
- 改善案: 生徒の端末で一度開いて確かめる。iPad の学校では、校内の Web サーバー（できれば https）に置いて、URL で開く方法を手引きの最初に書く。Chromebook でも、Google ドライブから開くとプレビューになるので「ダウンロードしてから開く」と書く。
- 手間: 小（手引きの書きかえ）
- ほかの教材にも: あり（6教材すべて）

## 4. よいところ（直すときに壊してはいけないこと）
- メニューの「はじめての人は、ここから」「おすすめの順番」「前回のつづき」「✓ 開いたことがある」。ノートPCでも最初の画面に入る。
- 教材を切りかえても、開いていた教材の作業が消えない。
- 「この端末の記録をすべて消す」は、確認のあとで、開いている教材を閉じてから消す（記録がもどらない）。表示の設定と先生が差し替えた問題は残す。
- 外部と通信しない。全教材で横にはみ出さない。
- 教材どうしをつなぐ案内（セキュリティラボ → デジタル化ラボ／ネットワーク通信シミュレータ）。

## 5. 先生に決めてほしいこと
1. **生徒の端末は何か**（KS-07）: iPad なら、配り方（校内 Web サーバー）を先に決める必要がある。Chromebook・Windows なら今のままでよい。
2. **ふりがなをどこまで広げるか**（KS-01）: (a) 教材集のバーに共通の「ふりがな」「大きな文字」を置く（おすすめ。手間は中で、6教材が一度にそろう）、(b) 各教材に1つずつ入れる、(c) 今のまま。
3. **記録の集め方**（KS-05）: (a) 6教材の記録を1つのファイルにまとめて書き出す（おすすめ。集める手間が6分の1）、(b) 今のまま教材ごと。
