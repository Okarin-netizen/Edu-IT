### CPU-01 課題7「最大値さがし」で、まちがったプログラム（JN end）が「クリア！」になる（チャレンジにも同じすきま）
- 改善計画: 第1段・1-B「判定と入力の受け付けを正しく」

  - 「JN ???」に「JN end」と書くと、4つのテストがすべて ○ になる。「小さい数が来たら終わり」と考える、よくある思いちがい。

    - 同じプログラムに 3, 1, 8, 0 を入れて実行すると、出力は 3（正しくは 8）。2, 9, 4, 10, 0 では 9（正しくは 10）。
  - ??? の埋め方を625通りすべてためした。
    - 合格は10通りで、そのうち4通りは、ランダムな入力400通りで答えをまちがえた。
    - 4通りは、JN end（または同じ番地の 8）と、STORE max（または同じ番地の 12）の組み合わせ。
    - 原因: 4つのテスト（3,8,2,0／5,1,0／1,2,3,4,0／7,7,0）のどれにも、「小さい数のあとに、もっと大きい数が来る」並びがない。

### CPU-03 課題5〜8と、番地・ACC・#・ラベル・DATA の読み書きが中2には重い。最後のヒントが答えそのもので、ボタン1つで答えが入る
- 改善計画: 第2段・2-4「むずかしすぎる所と時間の目安」
- 場所: ③課題（#/tasks、#/task/sum10・sumN・max・free）、②仮想CPU（#/sim）
- 観点: 難易度
- 重要度: B
- 確信度: 確認済み（ヒントと答えのしくみ）＋推定（生徒ごとのできる・できない、時間）
- 中学生の声: 「LOAD sum と LOAD #5 って何がちがうの？」「i ってどこにあるの？」（Bさん）、「ヒントを3回押したら答えが出た。入れるボタンでクリア」（Aさん）
- 何が起きているか:
  - 読み方の説明がたたまれている。#（数そのもの）と、名前・番号（その番地の中身）のちがい、ラベル、DATA の説明は、命令表の下の「書き方」4行にしかない。課題のページでは、その命令表がたたまれている。

    - DATA はなぜ HALT のあとに書くのか
    - 番地は0から、行番号は1から数える
    - ラベルは大文字・小文字を区別する
  - ヒントと答え:
    - ヒントは2〜3段で、最後はどの課題も答えそのもの（例:「ADD i と JUMP loop です。」「JN loop と STORE max です。」）。
    - そのあと「答えの例を見る」と「この答えをプログラム欄に入れる」が出て、押して答え合わせをすると「クリア！」になる。
    - 考え方のヒント（値の変わり方の表、流れ図、順次・分岐・反復）はない。
  - 課題ごとの見こみ（推定。○ できる／△ 時間がかかる・先生を呼ぶ／× ヒントの答えがないとできない）:

    | 5 | × | △ | ○ |
    | 6 | × | △ | ○ |

### CPU-04 エラー文が、まちがった直し方を教えることがある
- 改善計画: 第1段・1-C「まちがい・誤解をまねく説明を直す」
- 場所: ②仮想CPU（#/sim）・③課題（#/task/…）の赤い枠と「止まりました」の表示
- 観点: 操作・難易度
- 重要度: B
- 確信度: 確認済み（すべて実際に入力した。s37-follow-advice.mjs）
- 中学生の声: 「『end: DATA 0 のように用意しよう』って書いてあるから足したのに、もっとおかしくなった」（Bさん）
- 何が起きているか:
  1. ラベルが見つからないときは、とび先でもいつも「「end」という名前（ラベル）が見つかりません。「end: DATA 0」のように用意しよう」と出る。
     - チャレンジで end: を書き忘れた場合、言われたとおりに `end: DATA 0` を足すと、実行中に「8番地には命令ではなく数（0）が入っています。HALT を忘れていないか…」で止まる。
     - 課題4の `JUMP LOOP` に `LOOP: DATA 0` を足した場合も同じように止まる。
  2. 命令は大文字・小文字を区別しない（load でも動く）のに、ラベルは区別する。
     - 課題2で `ADD A`（a のつもり）と書くと、「「A」という名前（ラベル）が見つかりません。「A: DATA 0」のように用意しよう」と出る。
     - 言われたとおりに足すと、0 をたしてしまい、3, 5 の答えが 5 になる。
  3. 本当の原因が分からないメッセージになる:
     - DATA を先頭に書いたときも、空のまま実行したとき（チャレンジのはじめ）も、「0番地には命令ではなく数（0）が入っています。HALT を忘れていないか、とび先が正しいか確かめよう」と出る。
  4. # を忘れたときに、# の話が出ない:
     - 課題5で `SUB 11` と書くと「11番地には命令が入っていて、数として読めません」。
     - 課題1で `LOAD 12` と書くと、エラーなしで 0 が出て × になるだけ。
  5. そのほかの分かりにくい文:
     - 「LOAD # 5」→「1行に書ける命令は1つ、番地や数も1つだけです」
     - 「LOAD#5」→「「LOAD#5」という命令はありません」
     - 「DATA 2.5」→「「2.5」は数ではありません」（2.5 も数）

## 4. よいところ（直すときに壊してはいけないこと）
- 「1段階すすむ」で、取り出し→解読→実行を正確に説明している。光る装置、飛ぶ数、色のついたマス、説明の文がそろっている。PC は取り出しのときに進み、JZ/JN では「とぶ／とばない」の理由も文で出る。
- 書き方のゆれに強い。全角（ＬＯＡＤ ＃５）、小文字、空白・タブのずれ、日本語のラベル、ラベルだけの行、「;」「//」のコメントのどれでも動く。
- エラーの「4行目」をクリックすると、その行が選ばれる。??? の書きかえ、HALT 忘れ、入力が空、1万命令での自動停止（無限ループの説明つき）にはメッセージがある。
- 答え合わせ:
  - いくつもの入力の結果を表で見せる。
  - 答えを直接書いたとき（LOAD #55）は「△ くり返しを使っていない」と出る。
  - 正しい別解（JUMP 1、JN 0、STORE 12、JN を使った sumN）は合格にする。課題2〜6は、合格になるものがすべて本当に正しいことを総当たりで確かめた。
- 課題の足場がそろっている: ??? 入りの途中までのプログラム、段階的なヒント、答えの例、「はじめのプログラムにもどす」（確認あり）、「次の課題へ」。
- 書いたプログラム・クリア・保存したふりかえり・名前は、再読みこみやほかの教材への切りかえのあとも残る。
- 指で使える: ドラッグ操作がなく、iPad 縦はきれいに1列で入り、横へのはみ出しもない。
- ④は、自分の手計算の時間と、N を変えた同じプログラムをくらべる流れがよい。「手順がまちがっていれば、コンピュータはまちがった答えを速く出してしまいます」の一文や、ミリ・マイクロ・ナノ秒の説明もある。
- 図解は、データ（実線）と制御（点線）を分けている。「CPU＝制御装置＋演算装置」、主記憶と補助記憶の説明も正しく、クイズの正解もすべて正しい。
- 外部への通信は0件、コンソールのエラーも0件。作成者表示「作成：技術 岡田」がある。記録は端末の中だけに保存され、そのことが画面に書いてある。
