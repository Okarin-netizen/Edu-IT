# ネットワーク通信シミュレータ（はじめに・1〜5・ふりかえり・記録・つぎはこれ）中学生目線レビュー

> **この記録について**: 2026-10-13 に、教材集 第1版（情報の技術_体験教材集.html）の中でこの教材を中学生の立場で操作して書いたレビューの記録です。「画面例」のリンクから、その時の画面を開けます。.cjs・.mjs・work/… は、レビューのときに使った確認用のスクリプトと記録で、このフォルダには入れていません。各指摘の「改善計画」は、まとめの文書の段階（第1段〜第3段）を示します。教材のファイルはまだ書きかえていません。

対象: 教材集 `/mnt/project-files/kyozai-shu/release/情報の技術_体験教材集.html` の中の `iframe[data-id="network-sim"]`。
埋めこまれている中身は `network-sim/js`・`modules` のソースと1行ずつ同じことを確かめた（`work/extract.cjs`）。
画面は Playwright（Chromium）で、ノートPC 1366×650、タブレット横 1080×810・縦 810×1080 で操作した。指の操作は CDP のタッチで再現した。
再現スクリプトは同じフォルダの `s01-…cjs`〜`s25-…cjs`。道具は `touch.cjs`・`netstate.cjs`、ドリルの答えの計算し直しは `drillcheck/check.mjs`。

## 1. ひとことで
- 機器を置いて線でつなぎ、そのネットワークでパケットの流れ・故障・のぞき見を見られる、中学生にとって分かりやすい作りです。外部通信なし・`.example`・IPアドレスの範囲（説明用・プライベート）も守られています。1を作らずに2〜4へ進んでも、セキュリティラボから移ってきても、はじめの形のネットワークで体験できます。
- ただし、ノートPC（1366×650）ではアニメや結果が画面の外に出てしまい、いちばん見せたい「パケットが動くところ」を見のがしやすいです。3では、通り道でない所をこわしても「別の道を通りました」と出るため、誤解をまねきます。5のドリルは、説明のない2進数の変換とサブネット（/25・/28）が10問中4〜6問出ます。
- いちばん大事な指摘: **NW-01**（3の「別の道」の説明が事実と合わない）、**NW-02**（2のアニメ中にページが流れて図が見えない）、**NW-03**（5のドリルが説明なしに中学の範囲をこえる）

## 3. 指摘一覧

### NW-01 3で、通り道でない所をこわしても「別の道を通りました」と出る。太い線（いちばん近い道）も押すたびに入れかわる
- 改善計画: 第1段・1-C「まちがい・誤解をまねく説明を直す」
- 場所: 3 回線が切れたら？（#/fault）ステップ1・2
- 観点: 内容
- 重要度: A
- 確信度: 確認済み
- 中学生の声: 「DNSの線を切ったら道が変わった！ DNSの線もパケットが通ってたのかな？」（Bさん）／「スマホを止めたのに『別の道を通りました』って出た。スマホも道なの？」（Cさん）
- 何が起きているか:
  - 「ルータD と DNSサーバ の回線を切りました ✂。 いまこわれているところ：1か所」のあと「パケットを送る」を押すと、「届いた！ 道：わたしのPC → 家のルータ → ルータB → ルータD → くもストア（通った回線 4本） こわれたところをさけて、別の道を通りました。」と出る。切った線は通り道ではなく、道も変わっていない。「スマホ」を止めただけのときも同じ文が出る。どちらでも、ステップ1「1か所こわれても届く？」が「✓ できた」になる。
  - はじめの形では、わたしのPC→くもストアに同じ長さの道が2本ある（ルータA・C経由／ルータB・D経由）。どちらを太く表示するかを、毎回くじで決めている。関係ない線（ルータD–DNSサーバ）を切る・直すを6回くり返すと、太い線が B・D → A・C → A・C → B・D → B・D → A・C と入れかわった。画面の文は「太い線は、いまいちばん近い道です。」なので、「切ったから道が変わった」と見えてしまう。
  - この単元のねらい（経路が切れたら別の経路を通る）そのものについて、まちがった因果を覚えてしまう。
- 根拠: [11-fault-route-a.png](/mnt/project-files/reviews/2026-10-13_中学生目線レビュー/画面例/03_ネットワーク通信シミュレータ/11-fault-route-a.png)（切った直後、B・D経由）、[11-fault-route-b.png](/mnt/project-files/reviews/2026-10-13_中学生目線レビュー/画面例/03_ネットワーク通信シミュレータ/11-fault-route-b.png)（つなぎ直した直後、A・C経由）、[10-fault-detour.png](/mnt/project-files/reviews/2026-10-13_中学生目線レビュー/画面例/03_ネットワーク通信シミュレータ/10-fault-detour.png)、`s10-fault.cjs`・`s11-fault-random.cjs` の結果。/mnt/project-files/network-sim/modules/fault.js:57-60（こわすたびに道を選び直す）、fault.js:73（`faultCount()` が1以上なら必ず「別の道を通りました」）、fault.js:74（こわれた数だけでクリア）、/mnt/project-files/network-sim/js/netlib.js:90（同じ長さの道からくじで選ぶ）
- 改善案:
  - 道の選び方を毎回同じにする（前に表示した道がまだ使えるならそれを使う、など）。くじで道を変えるのは、2のパケットのアニメだけにする。
  - 「こわす前の道」と比べて文を分ける。
    - 道が変わったとき:「こわれたところ（家のルータ–ルータA）をさけて、別の道（家のルータ → ルータB → ルータD）を通りました。」
    - 道が同じとき:「こわれたところは、今回の通り道ではなかったので、同じ道で届きました。太い線（通り道）の回線を切ってみよう。」
  - ステップ1のクリア条件を「道が変わって届いたとき」にする。こわす前の道を点線で残すと、ちがいが目で分かる。
- 手間: 中
- ほかの教材にも: なし

### NW-02 2のアニメの間にページが勝手に下へ流れ、ノートPCでは図の上半分（パケットが通る道）が見えなくなる。止める・1つずつ進むもない
- 改善計画: 第2段・2-1「ノートPCの画面に収める」
- 場所: 2 Webページが届くまで（#/flow）ステップ1
- 観点: 操作
- 重要度: B
- 確信度: 確認済み
- 中学生の声: 「GETがどこを通ったか見てなかった。ページが勝手に下にいっちゃう」（Aさん）／「文を読んでいるうちにアニメが終わる。止められないの？」（Bさん）
- 何が起きているか: 「▶ 通信スタート」を押すと、①〜⑦の文が1行ふえるたびに、ページがその行までスクロールする。ノートPCでは、見えている図の高さが 482px 中 359px → 246px → 174px → 91px と減る。パケットが「わたしのPC → 家のルータ → ルータA → ルータC → くもストア」を通るころには、上半分（わたしのPC・ルータA・ルータC・くもストア）が画面の外になる。終わると図はほぼ見えず、組み立てたページ（ブラウザの絵）も画面の下にある。タブレット横でも 423px → 334px に減る（縦は全部見える）。速さは「ゆっくり／ふつう／はやい」を選べるが、止める・1つずつ進むボタンはない。もう一度見るのは「通信スタート」の押し直しでできる。
- 根拠: [08-flow-before-start.png](/mnt/project-files/reviews/2026-10-13_中学生目線レビュー/画面例/03_ネットワーク通信シミュレータ/08-flow-before-start.png)、[08-flow-during-packets.png](/mnt/project-files/reviews/2026-10-13_中学生目線レビュー/画面例/03_ネットワーク通信シミュレータ/08-flow-during-packets.png)、[08-flow-end-view.png](/mnt/project-files/reviews/2026-10-13_中学生目線レビュー/画面例/03_ネットワーク通信シミュレータ/08-flow-end-view.png)、`s08-flow.cjs`・`s20-flow-tablet.cjs` で測った値。/mnt/project-files/network-sim/modules/flow.js:42（`li.scrollIntoView`）、flow.js:126-130（図の下に文・表・ブラウザが続く）、/mnt/project-files/network-sim/js/netview.js:24-40（速さだけ）
- 改善案: `scrollIntoView` をやめ、ページを動かさない。広い画面では「図」と「①〜⑦の文」を左右にならべる（文は高さを決めた枠の中で流す）か、スクロールしても図が上に残るようにする。「⏸ 止める」「1つずつ進む（次へ）」ボタンを足し、①〜⑦の1つごとに止まれるようにする。
- 手間: 中
- ほかの教材にも: なし

### NW-03 5のドリルで、説明のない「2進数への変換」と「サブネット（/25・/28）の台数」が10問中4〜6問出る
- 改善計画: 第2段・2-4「むずかしすぎる所と時間の目安」
- 場所: 5 IPアドレス・ドリル（#/drill）ステップ2・3
- 観点: 難易度
- 重要度: B
- 確信度: 確認済み
- 中学生の声: 「255.255.255.240 って何？ /28 ってどういう意味？」（Bさん）／「68 を2進数にする方法、どこにも書いてない」（Aさん）／「8問以上が取れなくて何回もやり直してる」（Bさん）
- 何が起きているか:
  - ステップ1の説明は「どこまでがネットワーク部かはサブネットマスクで決めます。」と、255.255.255.0 の例だけ。2進数の変換のしかた（128・64・32…の重み）は出てこない。
  - それなのにドリルには「10進数の 68 を、2進数8けたで表すとどれ？」が出る（まちがいの選択肢は1けただけちがう）。「サブネットマスク 255.255.255.240（/28）のネットワークに、IPアドレスを割り当てられる機器は最大で何台？」も出る。答えたあとの解説も「68 = 01000100。IPアドレスの4つの数は、それぞれ8けたの2進数（8ビット）で、ぜんぶで32ビットです。」で、やり方は分からない。台数の解説の「ネットワークそのものを表す番号」「全員あての番号」も、ここで初めて出る。
  - 5000回分のドリルを作って数えると、2進数（2種類）と台数の問題は1回あたり4〜6問。/25・/28 の問題が入る回は67%。説明のある種類（書き方・同じネットワーク・機器の役目）だけ分かる生徒が「8問以上」をとれる確率は、1回あたり約12%。答えそのものは5万問すべて正しかった。
- 根拠: [15-drill-q-hosts.png](/mnt/project-files/reviews/2026-10-13_中学生目線レビュー/画面例/03_ネットワーク通信シミュレータ/15-drill-q-hosts.png)、[15-drill-q-bin.png](/mnt/project-files/reviews/2026-10-13_中学生目線レビュー/画面例/03_ネットワーク通信シミュレータ/15-drill-q-bin.png)、[15-drill-ip-tool.png](/mnt/project-files/reviews/2026-10-13_中学生目線レビュー/画面例/03_ネットワーク通信シミュレータ/15-drill-ip-tool.png)、`drillcheck/check.mjs` の結果。/mnt/project-files/network-sim/js/drilllib.js:52-76（toBinary・fromBinary・hosts、/24・/25・/28）、/mnt/project-files/network-sim/modules/drill.js:50（ステップ1の説明）、drill.js:90（8問以上でクリア）
- 改善案:
  - ステップ1の道具で、2進数の上に「128 64 32 16 8 4 2 1」の重みを出す。「1のところの重みを足すと10進数」「大きい重みから引いていくと2進数」を1行で書く。10進数→2進数の解説も、今の2進数→10進数の解説と同じ形で「68 = 64 + 4 → 01000100」のように出す。
  - 台数の問題は /24 だけにするか、「チャレンジ問題」にしてクリア条件（8問）から外す（5. 先生に決めてほしいこと）。
- 手間: 小〜中
- ほかの教材にも: あり（2進数の変換はデジタル化ラボでくわしく扱う。先にデジタル化ラボをやる前提なら、そのことを画面に書く）

## 4. よいところ（直すときに壊してはいけないこと）
- 外部に通信しない。出てくるサイトは `.example`、外のIPアドレスは説明用（203.0.113.x・198.51.100.x）、家の中とルータはプライベート（192.168.1.x・10.0.0.x）。生徒が機器を足しても、自動でこの範囲の番号が付く。
- 1で作った形が2〜4にそのまま使われ、作らなくても（はじめの形で）全部体験できる。セキュリティラボから4に直接来ても、すぐ体験できる。作ったネットワークは再読みこみしても残る。
- 2の①〜⑦の文と「送られるパケット」の表で、名前 → DNSへの問い合わせ → IPアドレス → お願い（GET）→ パケットに分ける → 別々の道 → 番号順に組み立て、の順番が追える。届いた順がばらばら（例「4 → 3 → 1 → 2 → 5（2とおりの道を通りました）」）でも組み立てられる、という体験がよい。
- 2は、DNSがない・DNSに届かない・Webサーバに届かない・機器がない・名前が見つからない、のそれぞれで理由の文が出る（3・4もこの形にそろえたい）。
- 3の「DNSサーバを止めると、Webサーバまでの道はつながっているのに名前では開けない」体験と、「冗長化」の説明。
- 4のHTTPSの画面は、送信元・宛先を出し、「行き先のサイト名…も見えることがある」「データの量は見えても」と言い切りをさけている。「鍵マークがあれば本物とは限らない」のクイズもよい。盗聴の具体的な方法にふれず、こわがらせすぎない。IDとパスワードは架空の固定値で、生徒に入力させない。
- 機器はタップ（クリック）で置けて、指でもドラッグで動かせる。矢印キーと、キーボード用の「つなぐ／外す」フォームがある。全ページ・3つの画面の大きさ・大きな文字で、横にはみ出さない。
- ドリルは毎回問題が変わり、答えは5万問すべて正しかった。解説が必ず出る。
- 記録（JSON・CSV）の書き出し、記録ページの下の「つぎはこれ」、ほかの教材に切りかえて戻っても作業が残ること。
